## Important open findings / areas

- **User report (2026-10-10):** Shards gained on a roll appear briefly, then the resource bar returns to zero. **Source-level root-cause path found and patched:** unsaved/new or legacy loaded states could omit `stateRevision`; the client skipped stale-response checks for a missing revision, allowing a delayed initial `/api/me` read (`Shards = 0`) to overwrite a successfully saved roll. `loadRaw()` now emits revision `0` for unsaved/new-generation states and normalizes legacy missing revisions; malformed stored revisions fail closed. Client snapshots are ordered by `(saveGeneration, stateRevision)`, so delayed reads from a previous save generation are ignored and wipes with lower revisions are accepted. Equal-revision conflicting Shards are still rejected. Fix commits: `93eb6709`, `e7c77ae4`; earlier defensive guard: `ac0b525`. The exact reported session has not been runtime-reproduced; classify root cause as **strongly inferred from code/data flow**, awaiting tests.

- Share-post publishing is an external side effect, while its local share cooldown/quest state is persisted afterwards. A successful Reddit submission followed by local save failure can leave a post without a corresponding local cooldown/attribution update. Needs idempotent request receipt/recovery; don't solve by pretending external publishing and Redis can be atomic.
- Corrupt ban registries still need a tightly authorized recovery/repair path that preserves raw data. Ordinary moderation writes should continue to fail closed.
